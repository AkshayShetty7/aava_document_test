1. React Fundamentals
A concise six-page guide to React fundamentals, hooks, state, performance, architecture, and
best practices.
What is React?
React is a JavaScript library for building user interfaces from reusable components. It is commonly used for
interactive web applications and can also be used with frameworks for routing, server rendering, and full-stack
development.
Components
A component is a reusable unit of UI and behavior. Components can be written as functions that receive inputs called
props and return a description of what should appear on screen.
JSX
JSX is a syntax extension that lets developers describe UI using an HTML-like syntax inside JavaScript. JSX is
transformed into JavaScript during the build process.
Props
Props are read-only inputs passed from a parent component to a child. They are useful for configuring reusable
components and communicating data down the component tree.
State
State represents data that can change over time and affect what a component renders. Updating state schedules a
new render so React can update the UI.
Declarative UI
React encourages declarative programming: describe what the UI should look like for a given state, and let React
handle the process of updating the DOM.

2. Rendering, Events & Component Composition
Rendering
React renders a component tree based on current props and state. When relevant data changes, React determines
what needs to change and commits the necessary DOM updates.
Virtual representation
React maintains an internal representation of the UI. This allows it to reason about changes efficiently rather than
requiring developers to manually manipulate every DOM node.
Events
React provides event handling through props such as onClick, onChange, and onSubmit. Event handlers are
functions that respond to user interactions and may update state.
Conditional rendering
JavaScript expressions such as ternary operators and logical AND can be used to render different UI depending on
application state or props.
Lists and keys
Arrays are commonly mapped into lists of components. Each sibling in a rendered list should have a stable key so
React can correctly track items across renders.
Composition
Instead of creating deeply specialized components, React encourages composition. Components can accept children
or other components, allowing flexible layouts and reusable UI building blocks.

3. Hooks: State, Effects & Reusable Logic
useState
useState lets a function component store local state. State updates should be treated as requests for a new render
rather than direct mutation of the existing state.
useEffect
useEffect is designed for synchronizing a component with external systems such as subscriptions, timers, browser
APIs, or network-related side effects. It should not be used merely to calculate derived values.
Dependency arrays
An effect's dependencies describe the reactive values it uses. Correct dependencies help React know when
synchronization needs to be repeated.
useRef
useRef provides a persistent mutable value that does not trigger a render when changed. It is often used for DOM
references or storing values that need to survive renders without affecting UI.
Custom hooks
Custom hooks package reusable stateful logic into functions whose names conventionally begin with use. They can
combine built-in hooks and application-specific behavior.
Rules of Hooks
Hooks should be called at the top level of React function components or custom hooks, not conditionally or inside
loops. Consistent call order lets React associate hook state correctly.

4. State Management & Data Flow
One-way data flow
React applications typically pass data from parent to child through props. Child components can communicate
upward through callback functions supplied by their parents.
Lifting state up
When multiple components need to coordinate around the same data, move the shared state to their nearest
common parent and pass the required values and callbacks downward.
Derived state
Avoid storing values that can be calculated from existing props or state unless there is a strong reason. Keeping
fewer sources of truth reduces synchronization bugs.
Context
Context lets data such as themes, localization, or shared application state be made available to components without
passing props through every intermediate component.
Reducers
useReducer is useful when state transitions are complex or when many updates follow explicit actions. A reducer
receives the current state and an action and returns the next state.
External state libraries
Larger applications may use dedicated state-management libraries. Choose them when application requirements
justify them; React's local state, props, context, and reducers can cover many use cases.

5. Routing, Forms & Performance
Routing
Client-side routing allows an application to display different views based on the URL without requiring a full page
reload. Routing libraries commonly support nested routes, parameters, navigation, and data loading.
Forms
Controlled inputs keep form values in React state, making validation and conditional behavior straightforward.
Uncontrolled inputs can be useful when direct DOM interaction is preferable.
Async data
Fetching data introduces loading, success, error, cancellation, caching, and synchronization concerns. Modern React
applications often use dedicated data-fetching or framework-level solutions.
Memoization
React provides tools such as memo, useMemo, and useCallback for specific performance cases. Memoization adds
complexity, so it should generally be guided by actual rendering or computation costs.
Code splitting
Dynamic imports and lazy loading can reduce initial JavaScript by loading parts of an application only when they are
needed.
Performance mindset
First measure. Look for unnecessary renders, expensive calculations, oversized bundles, excessive network
requests, and poorly designed component boundaries before adding optimization techniques.

6. Modern React Architecture & Best Practices
Server and client rendering
React can participate in client-side rendering, server rendering, static generation, and hybrid architectures.
Frameworks can combine these approaches to improve performance, SEO, and developer experience.
Server Components
React Server Components allow some components to execute on the server and send their rendered result or
component payload to the client. This can reduce client-side JavaScript for appropriate parts of an application.
Error handling
Production applications should handle failed requests, invalid input, unavailable services, and unexpected rendering
errors gracefully. Error boundaries can isolate certain rendering failures.
Accessibility
Use semantic HTML, labels, keyboard-accessible controls, meaningful focus management, and appropriate ARIA
only when necessary. Accessibility should be part of component design rather than a final patch.
Testing
Test behavior rather than implementation details where practical. Unit tests can cover logic, component tests can
cover UI behavior, and end-to-end tests can validate important user journeys.
Best-practice checklist
Keep components focused, use stable keys, avoid unnecessary effects, keep state close to where it is used, prefer
composition, handle async states explicitly, measure performance before optimizing, and design for accessibility from
the start.
