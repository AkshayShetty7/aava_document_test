1. What Is Generative AI?
A concise six-page guide to the foundations of generative AI.
Definition
Generative AI (GenAI) is a class of artificial intelligence systems that learns patterns from large datasets and uses
those patterns to generate new content such as text, images, audio, video, code, and structured data.
How it differs from traditional AI
Traditional AI often predicts, classifies, ranks, or detects. GenAI focuses on producing an output. For example, a
classifier may identify whether an email is spam, while a generative model can draft a reply.
Core idea
Most modern GenAI systems learn a probability distribution over data. Given context, they estimate plausible
continuations or outputs. The result can look original even though the model learned from existing examples.
Common applications
Chat assistants, document drafting, code generation, summarization, image creation, synthetic data, customer
support, search experiences, education, marketing, and creative tools.
Key vocabulary
Model: the learned system. Prompt: the input instructions/context. Inference: using a trained model to produce an
output. Token: a unit of text processed by many language models. Multimodal: able to work across multiple data
types.
Simple mental model
Think of GenAI as a powerful pattern-completion engine with a large learned representation of language or other
media. It does not simply retrieve a stored answer; it constructs an output step by step.

2. Large Language Models (LLMs)
What is an LLM?
A Large Language Model is a neural network trained on very large collections of text and other data. It learns
statistical relationships between tokens and can use context to generate coherent language.
Tokens and context
Text is split into tokens. During inference, the model considers a context window containing the current input and
available conversation or retrieved information. Larger context windows can support longer documents, but more
context does not automatically mean better reasoning.
Transformer architecture
Modern LLMs commonly use the Transformer architecture. Self-attention lets the model weigh relationships among
tokens, helping it connect relevant information across a sequence.
Pretraining
During pretraining, the model learns broad patterns from large datasets, often through objectives related to predicting
missing or next tokens. This creates general capabilities.
Post-training
Additional training can make models more useful, safer, and better aligned with instructions. Techniques include
supervised fine-tuning, preference optimization, and reinforcement-learning-based approaches.
Limitations
LLMs can hallucinate, misunderstand ambiguous instructions, inherit biases, struggle with exact calculations, and
produce confident but unsupported claims. Verification and grounding are important for high-stakes use.

3. Prompt Engineering & Context
Prompt engineering
Prompt engineering is the practice of designing inputs that clearly communicate the task, constraints, context, and
desired output. Good prompts reduce ambiguity and make evaluation easier.
A useful prompt structure
Role or goal → task → context → constraints → examples → output format → quality criteria. Not every prompt needs
every component; use only what improves the result.
Few-shot prompting
Provide a small number of examples showing the desired input-output behavior. This can help the model infer
formatting, tone, classification rules, or transformation patterns.
Structured outputs
When outputs feed software or workflows, specify a schema such as JSON fields, tables, or a fixed set of labels.
Structured outputs make downstream validation easier.
Context is not truth
Adding information to a prompt does not guarantee that the model will treat it correctly. Context should be
authoritative, relevant, and clearly separated from instructions.
Practical example
Instead of: 'Summarize this.' Use: 'Summarize the document for a senior manager in 5 bullets. Focus on decisions,
risks, owners, and deadlines. Do not invent missing facts.'

4. RAG, Embeddings & Knowledge
Why RAG?
Retrieval-Augmented Generation (RAG) connects a generative model to external information. Instead of relying only
on model parameters, the system retrieves relevant documents and supplies them as context before generation.
Embeddings
An embedding is a numerical representation of content designed so that semantically related items tend to be close in
vector space. Embeddings enable semantic search and similarity matching.
Typical RAG pipeline
Ingest documents → split into chunks → create embeddings → store in a vector index → embed the user query →
retrieve relevant chunks → place them in the prompt → generate an answer → optionally cite sources.
Chunking
Chunks should be large enough to preserve meaning but small enough for precise retrieval. Chunking strategy
depends on document structure, headings, tables, and the expected questions.
RAG vs fine-tuning
RAG is usually better when the goal is to provide changing or private knowledge at inference time. Fine-tuning is
often more useful for changing behavior, style, or task-specific patterns rather than simply adding a knowledge base.
RAG risks
Poor retrieval can lead to incomplete answers. Systems may retrieve irrelevant passages, miss the best source, or fail
to distinguish authoritative from outdated content. Retrieval quality should be evaluated separately from generation
quality.

5. AI Agents & Tool Use
What is an AI agent?
An AI agent is a system that uses a model to decide or propose actions, often across multiple steps, while interacting
with tools, data sources, software, or external environments.
Agent loop
A common pattern is: observe context → reason or plan → select a tool/action → execute → inspect the result →
continue or stop. The model may operate under explicit policies and limits.
Tools
Tools can include search, databases, calculators, code execution, calendars, APIs, file systems, or business
applications. Tool use lets the system obtain current information or take actions it could not perform from model
knowledge alone.
Agent vs chatbot
A chatbot primarily responds to messages. An agent can pursue a goal across multiple steps. The distinction is
practical rather than absolute; many modern assistants combine conversational and agentic behavior.
Guardrails
Use least-privilege access, approval checkpoints for consequential actions, input/output validation, timeouts, audit
logs, sandboxing, and clear boundaries around what the agent may change.
Evaluation
Test agents on task success, tool-selection accuracy, recovery from errors, safety violations, cost, latency, and
behavior under adversarial or ambiguous inputs.

6. Evaluation, Safety & The GenAI Stack
Evaluation
A GenAI application needs task-specific evaluation. Useful metrics can include factual accuracy, relevance,
completeness, groundedness, consistency, latency, cost, and user satisfaction. Human review is often valuable for
nuanced tasks.
Hallucinations
A hallucination is an output that presents unsupported or false information as if it were true. Retrieval, citations,
constrained generation, verification steps, and calibrated UX can reduce the risk but cannot guarantee zero errors.
Security & privacy
Protect sensitive data, control permissions, validate tool inputs, prevent prompt injection from untrusted content, and
avoid giving models unnecessary access. Treat model outputs as untrusted until validated.
Responsible AI
Consider fairness, transparency, privacy, intellectual property, misuse, accessibility, and accountability. High-impact
decisions should have appropriate human oversight.
Typical GenAI stack
Application/UI → orchestration → model(s) → retrieval/embeddings → tools/APIs → data stores →
monitoring/evaluation → security and governance.
Takeaway
Successful GenAI is not just about choosing a powerful model. The strongest systems combine good prompts,
reliable context, useful tools, robust evaluation, safety controls, and a clear user outcome.
